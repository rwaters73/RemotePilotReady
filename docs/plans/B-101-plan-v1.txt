4.7 New scripts/qbank/lib/figures.ts (pure, no I/O, no Poppler)

Constants (hardcoded literals):

- RENDER_DPI = 300
- EXPECTED_PAGE_COUNT = 113, PAGE_PT = {w: 594, h: 774}; the render is 2475 ×
3225
- INK_THRESHOLD = 250 (a pixel is ink if any channel is below 250)
- MARGIN_PX = 24 (about 2 mm)
- HEADER_PAD_PT = 3
- PPI_WARN = 330
- WEBP_PSNR_WARN_DB = 35
- WEBP = {quality: 90, effort: 6, smartSubsample: true, losslessForGrayscale: 
true}
- PNG = {compressionLevel: 9, adaptiveFiltering: true, palette: false}
- EXPECTED_FIGURES and EXPECTED_LEGENDS, written as explicit number arrays,
not ranges with exclusions
- KNOWN_NOT_IN_CONTENTS = ['fig-55']

Functions:

- parseBboxLayout(xhtml): reads Poppler pdftotext -bbox-layout output into
pages → lines → words with xMin, yMin, xMax, yMax in points. It decodes the
five XML entities and numeric entities.
- classifyPages(pages): a caption line is one whose text matches
^(Figure|Legend)\s+(\d+)\.(\s|$).
  - 0 caption lines: no item on the page.
  - 1: an item page.
  - 2: an error.
  - 3 or more: a contents page, whose entries are kept for the cross-check.
- Mapping checks: collect every problem before failing.
  - Duplicate key (name both pages).
  - Key not in the expected set.
  - Expected key not found.
  - Contents entries vs found items: any difference other than
KNOWN_NOT_IN_CONTENTS is an error, and fig-55 is reported as a note.
- Header detection, per item page:
  - The "Appendix N" group is the word Appendix plus the next word, which must
be a digit: 1 for legends, 2 for figures.
  - The page-number word matches ^[12]-\d{1,2}$, with the same appendix digit.
  - Exactly one of each, or it's an error.
  - Within an appendix, printed page numbers must rise by exactly 1 from one
item page to the next.
- headerBands(groups): works the same wherever the header sits.
  - Pad each group's bounding box by HEADER_PAD_PT and find the nearest page
edge.
  - The band runs from that edge to the far side of the padded box, across the
full page in the other direction.
  - It is an error if any non-header word overlaps a band.
- computeCrop(rgb, w, h, bands, words):
  - Find the bounding box of the ink pixels outside the bands.
  - Union it with every non-header word's box, converted to pixels with floor
and ceil.
  - Expand by MARGIN_PX, clamped to the page, and shrink only the margin where
it would enter a band.
  - Return the crop plus diagnostics:
    - inkOutside: ink outside the crop and bands. Must be 0, otherwise it's an
error and a bug.
    - faintOutside: pixels with any channel below 255 outside the crop and
bands. A warning, with count and box.
    - inkInBands: ink inside a band but outside the padded header word boxes.
A warning, with count and box.
    - touchesEdge: the sides where the crop reaches the page edge. A warning.
  - Also assert that the caption line and any line starting with NOTE: or
Note: are inside the crop.
- captionDirection(line): uses the vector from the centre of the word
"Figure"/"Legend" to the centre of the number word, identified by text, not by
Poppler's word order.
  - Mostly horizontal and pointing right: 0. Pointing left: 180.
  - Pointing down: rotate 270 clockwise. Pointing up: rotate 90 clockwise.
- checkRotations(file, items): the rotations file is the authority.
  - An entry with evidence: "caption" must match captionDirection.
  - A caption that isn't upright and isn't in the file is an error, with the
suggested angle given.
  - Entries with evidence: "visual" are not checked against text and are
listed in the report as "rotation confirmed by eye only".
  - Keys must be unique and in the expected set, and source_sha256 must match.
- isGrayscale(rgb): true only if every pixel has R = G = B.
- psnr(a, b).
- formatSizeReport(items).

4.10 New scripts/qbank/extract-figures.ts

Flags:

- --survey: writes nothing.
- --out DIR: default figures/ in the repo.
- --only KEY,…: refused unless --out points somewhere other than the repo's
figures/.
- --allow-version-change.

Usage errors are checked before the tools are looked up, and exit with code 2.

The script reads references/ only and never writes there.

Steps:

1. Preflight:
   - SHA-256 of the PDF must equal akts-2h.
   - figure-rotations.json must be valid and carry the same SHA-256.
   - pdfinfo -f 1 -l 113 -box: 113 pages, each 594 × 774 pt, rot 0, MediaBox =
CropBox. Anything else is an error.
   - pdffonts on each item page: any font that isn't embedded is a warning,
because Poppler would substitute a font and the render would vary from machine
to machine.
   - pdfimages -list gives the effective ppi of each page's images. Above
PPI_WARN is a warning.
2. Text: one call, pdftotext -bbox-layout -enc UTF-8 -f 1 -l 113 into a temp
folder, then parseBboxLayout.
3. Mapping: all the checks in 4.7. Stop on any error, listing all of them.
4. Header bands: as in 4.7. The survey prints which edge each header group
sits on.
5. Rotation: run checkRotations.
   - --survey stops here. For every page it prints: page, printed page number,
caption text, caption direction, header edges, highest image ppi, number of
fonts not embedded, and the rotations-file entry. Then it exits 0, or 1 if the
mapping failed.
6. Version guard: if --out already holds an index with items and its Poppler,
sharp or libvips version differs from the current tools, refuse without
--allow-version-change. The message warns that every file would get new bytes,
adding roughly 200 MB of new git history.
7. Per item:
   - Render with pdftoppm -r 300 -f P -l P -singlefile -png -aa yes -aaVector 
yes into the temp folder.
   - Decode with sharp to raw RGB and confirm the size is 2475 × 3225.
   - computeCrop, then crop, then rotate clockwise by rotate.
   - isGrayscale decides gray or RGB.
   - PNG: sharp png(PNG); gray images are written as one-channel 8-bit gray.
No metadata or ICC profile, and the output is treated as sRGB. Decode the
written PNG and require it to match the source pixels exactly, so the copy is
proven lossless.
   - WebP: gray images use webp({lossless: true, effort: 6}); colour images
use webp({quality: 90, effort: 6, smartSubsample: true}). Compute PSNR against
the source and warn below 35 dB.
   - All outputs go to the temp folder first.
8. Finish:
   - Only if every item succeeded, copy the files into --out, then write
index.json last.
   - Items are ordered figures by number, then legends by number. The JSON
uses 2-space indents, a trailing LF and no timestamps, so two runs with the
same tools give identical output.
   - Run verifyFigureFiles on --out and print the report.
   - Always delete the temp folder in a finally.
9. Report:
   - One line per item, for example: fig-26  p59  2-25  rot 0  crop 2240x2950 
rgb  png 6,012,345  webp 1,104,567 (q90, 41.2 dB).
   - Then every warning, grouped by item, then tool versions, then the size
report:
     - Items: 98 (79 figures, 19 legends); number rotated; number grayscale.
     - PNG: N files, B bytes (MiB) and WebP: N files, B bytes (MiB).
     - The five largest files of each format.
   - Exit 1 on any error; warnings don't change the exit code.

5. Dependencies and licences

None of these is paid or usage-limited, and none ships to the site.

- sharp (devDependency): Apache-2.0, free.
- Its prebuilt libvips (@img/sharp-libvips-*): LGPL-3.0-or-later, free. It is
used only as a local tool and not redistributed.
- libwebp, libpng, zlib, bundled inside libvips: BSD and zlib licences, free.
- Poppler (external program, not an npm package): GPL-2.0-or-later, free. We
run it and don't distribute it; the images it produces aren't covered by its
licence.
- No XML library is needed; Poppler's bbox output is parsed with regular
expressions.

Git LFS comes up in open question 3 only as an option. It has storage and
bandwidth limits, and charges beyond them.

7. Risks

1. Git history size. The PNGs are about 200 MB (your estimate; the size report
gives the real number), and history keeps every version. Re-running with the
same tool versions should give identical bytes (verified in section 9), so it
adds nothing. Different versions rewrite every file. Mitigations:
   - The eye check happens before commit 2.
   - The version guard (4.10, step 6) refuses to overwrite without
--allow-version-change.
   - figures:check means nobody ever needs to re-render just to verify the
images.
2. Poppler version differences: anti-aliasing, JPEG 2000 decoding (OpenJPEG),
any fonts that aren't embedded, and small shifts in text bounding boxes.
Mitigations:
   - Versions are recorded in the index.
   - pdffonts warnings.
   - The check mode doesn't use Poppler.
3. Xpdf passing as pdftotext on Windows. Handled by the refusal in 4.8.
4. Header position is unknown. The band rule assumes headers and page numbers
sit in edge strips.
   - A figure reaching into such a strip triggers the inkInBands warning.
   - A tab graphic behind "Appendix N" would show up the same way, or as a
crop touching the edge.
   - If the survey shows header graphics the rule doesn't handle, stop and
come back to the planner; the builder should not improvise.
5. Very light tints (above 250 in every channel) can sit outside the ink box.
Caught by the faintOutside warning and the eye check.
6. Rotation.
   - Captions catch sideways text.
   - A sideways raster with an upright caption can only be caught by eye, so
evidence: "visual" entries are listed in the report.
   - Upside-down output is caught by the eye check.
7. Linux workspace limits:
   - It needs Node 22.18 or later, because the scripts run as .ts directly;
fallback is nvm.
   - npm needs network access to install sharp's prebuilt Linux binaries;
fallback is npm install --no-save --os=linux --cpu=x64 sharp.
   - Rendering 98 pages at 300 dpi with JPEG 2000 images may take several
minutes; run it in the background, or batch with --only into a scratch folder.
   - The 176 MB PDF has to be in the workspace.
8. Downstream:
   - B-115: deploy only figures/*.webp. The PNGs must be kept out of the
Workers static assets (copy step or .assetsignore). Workers allows 25 MiB per
file, so the WebP files are fine.
   - B-106:
     - A sectional chart WebP is around 1–1.5 MB on a phone, and small chart
text needs pinch-zoom.
     - Smaller variants for phones could come later.
     - The index's width and height can be used to avoid layout shift.
   - B-103: questions that use a figure have to wait for commit 2.
9. content_hash doesn't cover images. If a figure changes after approval, the
approved question and past reviews change without a new review (D-051). It
shows only in the index.json diff. A backlog item is proposed in open
question 6.
10. Agents reading images.
    - A PNG of several MB may be over the image limit for Claude's Read tool.
    - Large images are scaled down when viewed, so q-reviewer may not be able
to read small sectional chart text even when users can at full zoom.
    - See open question 5.
11. Transfers through the desktop link have dropped writes before. Handled by
the SHA-256 check in figures:check.
