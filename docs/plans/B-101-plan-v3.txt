4.7 New: scripts/qbank/lib/figures.ts (pure: no I/O, no Poppler, no sharp)

Constants. Write all of these as literals. Don't compute or range-generate the
expected sets or the window bounds.

- RENDER_DPI = 300. S = 300/72 (points to pixels).
- EXPECTED_PAGE_COUNT = 113.
- PAGE_PT = {w: 594, h: 774}. PAGE_PX = {w: 2475, h: 3225}.
- INK_THRESHOLD = 250. A pixel is ink if any channel is below 250.
- MARGIN_PX = 24. This is the white margin around every image, and also the
gap between a turned body and its caption.
- PAD_PX = 4. Each crop is padded by this much, to keep anti-aliased edges.
- Page-mark windows, in points. They come from section 2's measured extents
plus 1.0 pt, and are used only to assert where the header and page number are.
They never decide what is removed.
  - HEADER_Y_PT = [32.8, 45.7]
  - HEADER_LEFT_X_PT = [35.0, 80.1]
  - HEADER_RIGHT_X_PT = [513.5, 559.0]
  - PAGENUM_X_PT = [268.0, 326.0]
  - PAGENUM_Y_PT = [727.0, 741.3]
  - A box is inside a window when xMin >= lo_x, xMax <= hi_x, yMin >= lo_y and
yMax <= hi_y.
- ERASE_PAD_PT = 0.25. The padding around each page-mark word box that is
erased. Never raise it: fig-65 leaves only 0.56 pt.
- CAPTION_TOL_PT = 1.0.
- MIN_WORD_CHARS = 3. MIN_DETECT_WORDS = 8. SIDEWAYS_SHARE = 0.65. These are
unchanged, and proven on the real data.
- DIRECTION_MIN_VOTES = 3. DIRECTION_AGREEMENT = 0.8.
- CAPTION_SIDEWAYS_MIN_CHARS = 4. CAPTION_SIDEWAYS_RATIO = 1.02.
- PPI_WARN = 330. WEBP_PSNR_WARN_DB = 35.
- WEBP = {quality: 90, effort: 6, smartSubsample: true, losslessForGrayscale:
true}.
- PNG = {compressionLevel: 9, adaptiveFiltering: true, palette: false}.
- EXPECTED_FIGURES and EXPECTED_LEGENDS: explicit arrays of numbers (1-15,
17-28, 31-82 written out; 1-19 written out).
- KNOWN_NOT_IN_CONTENTS = ['fig-55'].
- SAVE_WORDS_CONTROLS = ['fig-36', 'fig-43', 'fig-48'], the upright pages
nearest the detection line.

Character count. Everywhere: the word's trimmed text length in Unicode code
points ([...text.trim()].length).

Point-to-pixel conversion. Two rules, both with S = 300/72:
- Outward (for word boxes used in crops, caption zones and containment
checks): left = floor(xMin·S), top = floor(yMin·S), right (exclusive) =
ceil(xMax·S), bottom (exclusive) = ceil(yMax·S).
- Pixel-centre (for erasing only): a pixel (px, py) is erased when its centre
((px+0.5)/S, (py+0.5)/S) lies inside the box padded by ERASE_PAD_PT. That
gives:
  - first column = ceil((xMin - 0.25)·S - 0.5)
  - last column = floor((xMax + 0.25)·S - 0.5)
  - and the same for rows. Clamp to the page.
  - No pixel whose centre is more than 0.25 pt outside a word box is erased.
  - Worked example, fig-65: yMax 44.3 gives last erased row floor(185.125)
= 185. The border is at row 187, so row 186 is clear.

Text and mapping.

- parseBboxLayout(xhtml): reads Poppler pdftotext -bbox-layout output into
pages, then lines (keeping Poppler's line grouping and word order), then words
with xMin, yMin, xMax, yMax in points. It decodes the five XML entities and
numeric entities.
- classifyPages(pages): a caption line is one whose text matches
^(Figure|Legend)\s+(\d+).(\s|$).
  - 0 caption lines: not an item page.
  - 1: an item page.
  - 2: an error.
  - 3 or more: a contents page. Its entries are kept for the cross-check.
- Mapping checks. Collect every problem before failing:
  - Duplicate key (name both pages).
  - Key not in the expected set.
  - Expected key not found.
  - Contents entries vs. found items: any difference other than
KNOWN_NOT_IN_CONTENTS is an error. fig-55 is reported as a note.

Page marks: checkPageMarks(page). This replaces v2's fixed strips. It returns
the three mark words, the header side and errors. Every error names the page,
the word, its box and the window.

- Header:
  - Candidates are words with text exactly "Appendix" whose box is inside
HEADER_Y_PT and inside HEADER_LEFT_X_PT or HEADER_RIGHT_X_PT.
  - There must be exactly one candidate.
  - The next word on its Poppler line is the digit: "1" for a legend, "2" for
a figure. Its box must be inside the same side's window.
  - Record the side.
  - If there are 0 candidates, the error lists every "Appendix" word on the
page with its box.
- Page number:
  - Exactly one word must lie inside the page-number window (PAGENUM_X_PT x
PAGENUM_Y_PT).
  - It must match ^[12]-\d{1,2}$ with the right appendix digit.
  - If there are 0 or 2+, the error lists every word matching ^[12]-\d{1,2}$
on the page, and every word inside the window.
- Words matching ^[12]-\d+$ or "Appendix" outside the windows are content, not
marks.
- Overlap: any other word whose box intersects (positive area) a mark word's
box padded by ERASE_PAD_PT is an error: "word 'X' [box] on page P overlaps the
header/page number". This replaces v2's "word in a strip" error. Such a word
would be partly erased.
- Within an appendix, printed page numbers rise by exactly 1 from one item
page to the next.
- Words anywhere else on the page, including above y 48 pt, are content.

Partition into body and caption block (text): partitionWords(page, marks).

- Content words: every word except the three mark words.
- Caption line top: the smallest yMin among the caption line's words.
- Caption-block words: content words with yMin >= caption line top -
CAPTION_TOL_PT. That is the caption line plus every line printed beneath it.
- Body words: every other content word.
- Body lines: Poppler's lines filtered to body words, keeping order, with
empty lines dropped. Caption lines are built the same way.
- Error: no body words and (later, from pixels) no body ink. Message: "nothing
printed above the caption on page P".

Orientation detection: detectOrientation(bodyWords). Unchanged.

- Count body words with at least MIN_WORD_CHARS characters. A word is sideways
if (yMax - yMin) > (xMax - xMin).
- n = the counted words. share = sideways / n.
- Result:
  - n < MIN_DETECT_WORDS: "undetermined" (a raster or sparse body).
  - share >= SIDEWAYS_SHARE: "sideways".
  - Otherwise: "upright".
- Return n, the sideways count and the share. Note: 13/20 === 0.65 in IEEE
doubles, because division is correctly rounded.
- Why these values: on the real PDF the 13 sideways items all have n >= 21,
and the nearest upright pages score 0.35 and 0.32.

Direction: detectDirection(bodyLines), for "sideways" results only.

- Within each body line, every pair of adjacent words (w_i, w_i+1) where both
have at least MIN_WORD_CHARS characters and both are sideways is one vote.
Pairs separated by a non-qualifying word don't vote.
  - dy = centreY(second) - centreY(first).
  - dy < 0 is bottom-to-top ("up").
  - dy > 0 is top-to-bottom ("down").
  - dy = 0 is ignored.
- Result: {direction, up, down}. direction is:
  - 90 when up + down >= DIRECTION_MIN_VOTES and up / (up + down) >=
DIRECTION_AGREEMENT
  - 270 when the same holds for down
  - otherwise null.
- null is not an error here; compareRotations decides what it means.
- Bottom-to-top text needs rotate 90 (clockwise). Top-to-bottom text
needs 270.
- This relies on Poppler listing a rotated line's words in reading order,
which architect-Claude confirmed (section 2).

Caption-block sideways check: findCaptionSideways(captionWords). New in v3.

- Returns the caption-block words with at least CAPTION_SIDEWAYS_MIN_CHARS (4)
characters and (yMax - yMin) > CAPTION_SIDEWAYS_RATIO x (xMax - xMin),
written with the multiplication, not a division.
- Why: short upright words reach 1.09 (the figure number, "Air", "vs."). For
4+ character words, upright never exceeds 1.00 and real sideways words start
at 1.04. A limit of 1.02 sits midway, with 0.02 of margin on each side.
- This rule is separate from detection's on purpose. Detection judges a page
share where a few short-word misreadings don't matter. This check fires on a
single word.
- A sideways word of 1-3 characters is not caught here (risk R6).

Rotations file.

checkRotationsFile(raw, docs) rejects:
- Keys other than source_doc, source_sha256, rotations.
- source_doc that isn't "akts-2h".
- source_sha256 that differs from akts-2h in docs.
- An entry whose keys aren't exactly key, rotate, evidence.
- A key that is malformed, not in the expected set, or listed twice.
- rotate not 90, 180 or 270 (0 is never listed).
- evidence not "words" or "visual".
- evidence "words" with rotate 180 (detection can't see upside down).

compareRotations(file, detections) returns errors and notes. Every case:

- K1. Sideways, direction 90/270, no entry. Error: "KEY is printed sideways (S
of N body words); add { "key": "KEY", "rotate": R, "evidence": "words" }".
- K2. Sideways, direction 90/270, evidence "words", same rotate. Accepted.
- K3. Sideways, direction 90/270, evidence "words", different rotate. Error
naming both angles and the votes.
- K4. Sideways, direction 90/270, evidence "visual". Error: "KEY's direction
was found from its words (votes up U, down D); set evidence to words".
- K5. Sideways, direction null, no entry. Error: "KEY is printed sideways (S
of N body words) but its reading direction can't be read from its words (votes
up U, down D); look at the page and add { "key": "KEY", "rotate": 90 or 270,
"evidence": "visual" }".
- K6. Sideways, direction null, evidence "visual", rotate 90 or 270. Accepted,
and listed in the report as "sideways detected, direction confirmed by eye
only".
- K7. Sideways, direction null, evidence "visual", rotate 180. Error: "KEY is
printed sideways; rotate must be 90 or 270".
- K8. Sideways, direction null, evidence "words". Error: "KEY's reading
direction can't be read from its words (votes up U, down D); use evidence

- K9. Upright, any entry. Error: "the rotations file turns KEY, but its body

- K10. Undetermined (n < 8), evidence "words". Error: "KEY has too few body

- K11. Undetermined, evidence "visual". Accepted, and listed as "rotation
confirmed by eye only".
- K12. Undetermined, no entry. Rotate 0, listed as "undetermined; upright by
default; check by eye".

Pixels, crops and composition. All functions take raw 8-bit RGB buffers (3
channels, row-major) plus their width and height.

- erasePageMarks(rgb, w, h, marks): returns a copy of the render with each
mark word's pixel-centre erase rectangle set to 255, plus diagnostics:
  - Error if any erase rectangle contains no ink before erasing: "no ink
inside the WORD box on page P". This catches a mismatch between text
coordinates and the render.
  - Warning eraseTouch: ink in the 1-pixel ring directly outside any erase
rectangle (clamped to the page, excluding pixels inside another erase
rectangle). It gives the count, the box and which mark. This flags header
glyphs that overhang their box, or content that runs into a mark box.
  - All later steps (crops, diagnostics, composition) use the erased copy.
That keeps the bottom rows of "Appendix 2" out of fig-65, whose crop starts at
row 183, inside the header's rows.
- computeCrops(erased, words, partition, rotated) returns body_px, caption_px
and diagnostics.
  - capTopPx = floor(caption line top x S) - PAD_PX.
  - Caption zones: each caption-block word box (outward conversion), padded by
PAD_PX.
  - Each ink pixel in the erased render is classified:
    - Above capTopPx: body ink.
    - At or below capTopPx and inside a caption zone: caption ink.
    - At or below capTopPx and outside every caption zone: when rotated, error
"ink beside the caption block on page P" (count and box); when upright, body
ink.
  - Body tight box = bounding box of the body ink and the body word boxes.
Caption tight box = bounding box of the caption ink and the caption-block word
boxes.
  - When rotated: error if the body tight box's bottom edge (exclusive) is
below capTopPx: "body reaches the caption block on page P".
  - When rotated: error if findCaptionSideways(caption-block words) is not
empty: "caption block on page P contains sideways text: WORD [box] ratio R".
  - Error if the body tight box is empty.
  - body_px = the body tight box padded by PAD_PX, clamped to the page
(columns 0-2474, rows 0-3224). When rotated, its bottom is also clamped to
capTopPx.
  - caption_px = the caption tight box padded by PAD_PX, clamped to columns
0-2474 and rows capTopPx-3224.
  - Source region R: for upright items, U = the smallest rectangle containing
body_px and caption_px. For rotated items, the two rectangles themselves.
  - Diagnostics:
    - inkOutside: ink in the erased render outside R. Must be 0; anything else
is an error and a bug.
    - faintOutside: pixels with any channel below 255 in the erased render
outside R. A warning, with the count and the box.
    - touchesEdge: a crop that reaches row 0, row 3224, column 0 or
column 2474. A warning naming the side. fig-19 is expected to warn "left" (its
chart starts at x 0).
  - Every content word must lie inside body_px or caption_px (outward
conversion). If not, it's an error and a bug.
- cropRgb(rgb, w, h, rect) returns the rectangle.
- rotateRgb(rgb, w, h, angle): exact pixel mapping, with no resampling. For
output pixel (x, y):
  - 90: output is h wide and w high; out(x, y) = in(y, h - 1 - x).
  - 180: output is w by h; out(x, y) = in(w - 1 - x, h - 1 - y).
  - 270: output is h wide and w high; out(x, y) = in(w - 1 - y, x).
- composeItem(erased, item fields) builds the final image on a white (255)
canvas, with M = MARGIN_PX:
  - rotate 0: the canvas is U.w + 2M wide and U.h + 2M high. Paste the erased
render's U at (M, M).
  - rotate 90, 180 or 270: B = rotateRgb(cropRgb(body_px), rotate) and C =
cropRgb(caption_px). The canvas is max(B.w, C.w) + 2M wide (W) and B.h + C.h +
3M high. Paste B at (floor((W - B.w) / 2), M) and C at (floor((W - C.w) / 2),
2M + B.h).
- isGrayscale(rgb): true only if every pixel has R = G = B.
- psnr(a, b).
- versionGuardDecision(existingIndex, currentVersions, allowFlag).
- formatSizeReport(items).

4.10 New: scripts/qbank/extract-figures.ts

Flags:

- --survey: writes nothing, except with --save-words.
- --save-words FILE: only together with --survey.
  - After a survey with no errors, it writes exactly one file, FILE, in the
format in 4.12a.
  - FILE must not be inside references/ or figures/.
- --out DIR: default is the repo's figures/.
- --only KEY,...: refused unless --out points somewhere other than the repo's
figures/.
- --allow-version-change.

Usage errors are checked before any tool lookup and exit with code 2. Usage
errors include:
- --save-words without --survey
- --save-words into references/ or figures/
- --only without --out.

The script reads references/ only and never writes there.

Steps:

1. Preflight:
   - The PDF's SHA-256 must equal akts-2h.
   - data/figure-rotations.json must pass checkRotationsFile.
   - Poppler lookup (4.8).
   - pdfinfo -f 1 -l 113 -box: 113 pages, each 594 x 774 pt, rot 0, MediaBox =
CropBox. Anything else is an error.
   - pdffonts on each item page: a font that isn't embedded is a warning.
   - pdfimages -list: an image above PPI_WARN is a warning.
2. Text: one call, pdftotext -bbox-layout -enc UTF-8 -f 1 -l 113, into a temp
folder. Then parseBboxLayout.
3. Mapping: all the mapping checks in 4.7.
4. Page marks: checkPageMarks on every item page. Report how many headers are
on each side (expected: 48 left, 50 right).
5. Partition and detection:
   - partitionWords, detectOrientation, and for sideways pages
detectDirection.
   - For every item that is detected sideways or listed in the rotations file,
run the text-only partition checks:
     - findCaptionSideways on the caption block.
     - A body word reaching the caption rows.
     - No body words. On text pages this is an error here; on undetermined
pages, wait for the pixel check.
6. Rotations: compareRotations.
   - --survey prints one block per item page and stops here. Each block has:
     - Page, printed page, key and caption text.
     - The caption block's extra lines.
     - Header side and the three mark boxes.
     - n, sideways count, share, result, and direction with votes.
     - The caption block's highest height/width ratio among 4+ character
words.
     - The rotations-file entry.
     - Highest image ppi and fonts not embedded.
   - Then it prints:
     - a "suggested entries" JSON block with one {"key", "rotate", "evidence":
"words"} per sideways item with a direction, in index order
     - "sideways, direction unreadable; set by eye (90 or 270), evidence
visual" with the keys (expected: fig-3, fig-82)
     - the undetermined items for an eye check.
   - Exit codes: 1 if steps 1-5 found any error, otherwise 0. Differences
between the rotations file and detection (K1, K3-K10) are printed as "to do",
not errors, because the file is being prepared. With --save-words, the file is
written only when the exit code is 0.
   - Without --survey, any compareRotations error stops the run with exit 1.
7. Version guard: if --out already holds an index with items, and its Poppler,
sharp or libvips version differs from the current tools, refuse without
--allow-version-change. The message warns that every file would get new bytes,
adding roughly 200 MB of new git history.
8. Per item. Collect errors across all items and keep going:
   - Render: pdftoppm -r 300 -f P -l P -singlefile -png -aa yes -aaVector yes
into the temp folder.
   - Decode with sharp to raw 3-channel RGB. Require 2475 x 3225 and 3
channels.
   - rotate = the rotations-file entry, or 0.
   - Run erasePageMarks, then computeCrops on the erased copy (rotated =
rotate is not 0), then composeItem from the erased copy. Assert the composed
size equals the formula in 4.7.
   - isGrayscale decides gray or RGB.
   - PNG:
     - Write with sharp from the composed raw buffer, using the PNG settings.
Gray images are one-channel 8-bit gray. No metadata or ICC profile; the output
is treated as sRGB.
     - Decode the written PNG and require it to match the composed pixels
exactly.
   - WebP:
     - Gray images: webp({lossless: true, effort: 6}).
     - Colour images: webp({quality: 90, effort: 6, smartSubsample: true}).
     - Decode the WebP and compute PSNR against the composed pixels. Warn
below 35 dB (lossy only).
   - All outputs go to the temp folder first.
9. Finish:
   - Only if every item succeeded, copy the files into --out, then write
index.json last.
   - Items are ordered figures by number, then legends by number.
   - The JSON uses 2-space indents, a trailing LF and no timestamps, so two
runs with the same tools and rotations file give identical output.
   - extracted_with.libvips comes from sharp.versions.vips.
extracted_with.erase_pad_pt is ERASE_PAD_PT.
   - Run verifyFigureFiles on --out and print its report.
   - Always delete the temp folder, in a finally block.
10. Report:
    - One line per item, for example:
      legend-1  p13  1-1  rot 90 (words)  body 2050x2700  caption 560x60  out 
2748x2182  gray  png 3,456,789  webp 1,234,567 (lossless)
    - Then every warning, grouped by item.
    - Then the "sideways detected, direction confirmed by eye only", "rotation
confirmed by eye only" and "undetermined" lists.
    - Then the tool versions.
    - Then the size report:
      - Items: 98 (79 figures, 19 legends), the number rotated (words /
visual) and the number grayscale.
      - PNG: N files, B bytes (MiB). WebP: N files, B bytes (MiB).
      - The five largest files of each format.
    - Exit 1 on any error. Warnings don't change the exit code.

7. Risks

- R1. Git history size. The PNGs are about 200 MB, and history keeps every
version. Re-running with the same tools gives identical bytes (checked in
section 9), but different tool versions rewrite every file. Mitigations: the
eye check and the 300 MB gate both come before commit 2; the version guard;
and figures:check, so nobody re-renders just to verify.
- R2. Poppler version differences: anti-aliasing, JPEG 2000 decoding, fonts
that aren't embedded, and small bbox shifts.
  - The window assertions, the detection share and the caption ratio depend on
bbox output.
  - Versions are recorded, and the check mode doesn't use Poppler.
  - A header or page number that moves out of its window fails loudly. It
never changes what is erased, because erasing follows the actual word boxes.
- R3. Xpdf passing as pdftotext on Windows. Handled by the refusal in 4.8.
- R4. Page marks and erasing.
  - Only the three mark words' boxes are erased (0.25 pt pad, pixel-centre
rule). Content that runs into a mark box would be partly erased. The overlap
error (words), eraseTouch (ink) and the eye check catch it.
  - fig-65 has 1 pixel row of clearance (row 186). B13 and A6 guard it.
  - If eraseTouch fires on most pages, the glyphs overhang their boxes. Stop
and bring it to the planner. Never raise ERASE_PAD_PT, never widen the
windows, and never turn an error into a warning.
  - Ink anywhere else on the page, including above y 48 or near the bottom, is
now content. On rotated pages, ink below the caption top outside the caption
zones fails loudly. v2's strips hid such ink; architect-Claude's run found it
only at the top, on fig-19 and fig-65.
- R5. Very light tints (above 250 in every channel) outside the ink box are
not copied, because margins are white canvas. Caught by the faintOutside
warning and the eye check.
- R6. Rotation.
  - Detection and direction use Poppler's word boxes and word order, confirmed
on the real data. Wrong word order would flip 90 and 270, which B9, B11 and
the eye check catch.
  - fig-3 and fig-82 rest on the eye check alone (K6). They are listed in the
report and pinned in B10.
  - Raster bodies and upside-down pages are found only by eye. Every
undetermined item and every "visual" entry is listed in the report.
  - The caption-block checks assume the caption sits below the body with
nothing beside it on sideways pages. If not, the run fails loudly.
  - A sideways word of 1-3 characters in the caption block isn't caught by
findCaptionSideways. It is left to the ink-beside-caption check (when it isn't
in a caption zone) and the eye check.
- R7. Runtime: rendering 98 pages at 300 dpi with JPEG 2000 may take several
minutes. Run it in the background, or batch with --only into a scratch folder.
The 176 MB PDF must be in the workspace.
- R8. Real-data test literals.
  - B13's rows 187 and 195 are architect-Claude's 300-dpi measurements. If its
threshold for "ink" differed from INK_THRESHOLD, B13 could fail on a correct
image.
  - B16's n >= 21 assumes the same character counting as architect-Claude's
run.
  - Either failure means stop and report, not edit.
- R9. Downstream:
  - B-115: deploy only figures/*.webp. Keep the PNGs out of the Workers static
assets with a copy step or .assetsignore. Workers allows 25 MiB per file.
  - B-106: a sectional chart WebP is about 1-1.5 MB on a phone, and small
chart text needs pinch-zoom. Turned items are landscape-shaped and read best
with the phone in landscape. Use the index's width and height to avoid layout
shift.
  - B-103: figure questions wait for commit 2.
- R10. content_hash doesn't cover images. A changed figure after approval
changes the approved question and past reviews without a new review.
Architect-Claude is adding a backlog item for B-116: the loader stores each
figure's SHA-256 and fails if a figure used by a loaded question changes.
- R11. Agents reading images.
  - A PNG of several MB may exceed the Read tool's image limit, which is why
agents will open the WebP.
  - Large images are scaled down when viewed, so q-reviewer may not be able to
read small chart text. A zoom command is going to the backlog; it is out of
scope here.
- R12. The desktop link has silently kept old content before, and caches by
source path.
  - figures:check catches any image that doesn't match the index.
  - The three reported SHA-256 values catch a stale index.json,
figure-rotations.json or figure-words.json.
  - Re-sends go from fresh paths.
- R13. A crop or composition bug that drops content silently. Mitigations:
  - inkOutside must be 0, and every content word must be inside a crop.
  - rotateRgb is tested pixel-exact.
  - B13 checks the two near-header edges on the real images.
  - The architect checks all 98 items by eye.
