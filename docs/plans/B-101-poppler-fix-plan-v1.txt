4.1 scripts/qbank/lib/poppler.ts

F1. Line 5: import { execFileSync, spawnSync } from 'node:child_process';
(runTool still uses execFileSync.)

F2. Replace lines 35-45 (the comment and versionOutput) with:

  // Runs a program with an argument array (never a shell) and returns its
  // stdout followed by its stderr, whatever the exit code. Poppler prints its
  // -v text on stderr and exits 0; Xpdf prints it on stderr and exits 99.
  // Both streams are read in every case. If the program could not be started
  // and printed nothing, the spawn error's message is returned.
  export function readVersionText(command: string, args: readonly string[]):
string {
    const r = spawnSync(command, args, { encoding: 'utf8', stdio: ['ignore',
'pipe', 'pipe'] });
    const out = `${r.stdout ?? ''}${r.stderr ?? ''}`;
    if (out === '' && r.error !== undefined) return r.error.message;
    return out;
  }

  export type VersionReader = (path: string) => string;

  // Runs `tool -v`.
  function versionOutput(path: string): string {
    return readVersionText(path, ['-v']);
  }

  - Don't pass a shell option or an env option, and don't add a timeout. Keep
the same stdio as before.
  - Order stays stdout then stderr, as the old catch did.

F3. findPoppler's signature becomes:

  // readVersion can be replaced so tests can run a stand-in program;
  // the scripts always use the default.
  export function findPoppler(
    env: NodeJS.ProcessEnv = process.env,
    readVersion: VersionReader = versionOutput,
  ): { tools: PopplerTools | null; errors: string[] } {

and line 57 becomes: const out = readVersion(path);

F4. Change nothing else. Every message string, the Xpdf branch, the
"poppler" test before the "Glyph & Cog" test, the version regex, the
same-version rule, locateTool, exeName, POPPLER_TOOLS and runTool stay
byte-for-byte the same.

One behaviour change, on purpose: a tool that exits non-zero and prints
nothing used to return execFileSync's err.message ("Command failed: <path>
-v"), which includes the path. That text was then checked for "poppler". The
new code returns "" in that case, so the error is "<tool> at <path> is not
Poppler …". It's an error both ways. The new way stops a folder name like
C:\tools\poppler-24.08.0\ from passing the "poppler" test. A spawn error with
no output still returns the error message, as before.

4.2 New: scripts/qbank/test/poppler.test.ts

Imports only node built-ins (node:test, node:assert/strict,
node:child_process is not needed, node:fs, node:os, node:path) and
'../lib/poppler.ts'. Nothing else, so the tester can copy the file and the lib
file into a temp folder for the mutation check.

Helpers:
- TOOLS: a literal ['pdfinfo', 'pdftotext', 'pdftoppm', 'pdfimages',
'pdffonts'], with a comment saying it is deliberately not POPPLER_TOOLS: a
test sourced from the constant under test can't catch a member disappearing.
- exe(t): process.platform === 'win32' ? `${t}.exe` : t.
- withBin(fn): mkdtempSync(join(tmpdir(), 'qbank poppler-')). The space is on
purpose, so the messages carry a path with a space. Write an empty
placeholder file for each tool, call fn(dir, env) with env = { POPPLER_BIN:
dir, PATH: '' }, and rmSync the folder in finally. The placeholders only
satisfy locateTool's existsSync; they are never run.
- program(stdout, stderr, exitCode): returns ['-e', code], where code is
  `process.stdout.write(${JSON.stringify(stdout)});
process.stderr.write(${JSON.stringify(stderr)}); process.exitCode =
${exitCode};`
  Use process.exitCode, not process.exit(), so the pipes drain before the
child exits. On Windows, a write to a pipe can be asynchronous.
- reader(spec): returns a VersionReader. For a path it takes the tool name
(basename without .exe), looks up {out, err, code} in spec, and returns
readVersionText(process.execPath, program(out, err, code)). Each call starts
a real child process; nothing is mocked.
- POPPLER(t, v): the literal
  `${t} version ${v}\nCopyright 2005-2024 The Poppler Developers -
http://poppler.freedesktop.org\nCopyright 1996-2011, 2022 Glyph & Cog, LLC\n`
  This is the shape of Poppler 24.02.0's -v text. The Glyph & Cog line is
included on purpose: real Poppler prints it too, so this also proves Poppler
is recognised before the Xpdf branch.
- XPDF(t): `${t} version 4.00\nCopyright 1996-2017 Glyph & Cog, LLC\n` (the
text checked on the desktop, exit 99).
- msgs(dir, template): builds the five expected error strings with join(dir,
exe(t)), in TOOLS order.
